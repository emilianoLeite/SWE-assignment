## What was built this session

### Prototype (throwaway, kept as visual reference)

A Next.js prototype lives at `apps/web/src/app/prototype/unified-inbox/` and runs at `http://localhost:3000/prototype/unified-inbox?variant=A`.

Three layout variants were built (`?variant=A/B/C`), Variant A was chosen. Variants B and C are still in the codebase as throwaway code — **do not promote them; delete when the real page is built.**

**Variant A layout (confirmed):**
- Full-width dark top bar (stats: AI replies, outbound messages, voce min, billing)
- Left sidebar: TextYess nav shell, `All Conversations` active + NEW badge
- Three-column content area:
  - **Left `w-[272px]`**: Customer list, sorted by `lastActivityAt` desc. Each row: name, preview, urgency status badge, timestamp. Selected row: left border `primary-500`.
  - **Center `flex-1`**: Page header ("All Conversations" + Filter + New Chat). Conversation header (customer name · phone, `+ MANAGE TAGS` / `BLOCK` buttons, Add assignee right). Scrollable cross-channel timeline of **Conversation Blocks** (consecutive same-channel messages grouped, color-coded by channel). Reply bar at bottom (channel tabs, input, **AI active/not active toggle**, Send).
  - **Right `w-60`**: Customer details panel matching `mockups/customer_details.png`: ALL-CAPS field labels, Email, Phone, Customer for, Lifetime spend, Tags, Edit contact info, Notes, Last order card.

**Key business rules already wired in the prototype:**
- AI toggle in the reply bar controls whether the input is enabled (WhatsApp/Email only)
- On-site and Voice channels: no reply box
- Reply channel tabs: disabled if customer has no conversation in that channel

### Domain model (from `CONTEXT.md`)

Key entities for implementation:

| Collection | Key fields |
|---|---|
| `customers` | `name`, `email`, `phone`, `lifetimeSpend`, `tags[]`, `notes`, `visitorId` (sparse), `lastOrder` (embedded), `lastActivityAt`, `createdAt` |
| `conversations` | `customerId`, `brandId`, `channel` (whatsapp/email/voice/onsite), `status` (ai_controlled/to_manage/managed/blocked/human_controlled), `type` (inbound/outbound), `assigneeId` (nullable), `aiActive` (bool), `campaign` (nullable string), `lastActivityAt`, `channelData` (sub-doc) |
| `messages` | `conversationId`, `sentBy` (customer/ai/operator), `content`, `sentAt`, `type` (text/button/media) |
| `operators` | `name`, `email` — seed 3–4 |

**Voice special case:** transcript embedded in `channelData.transcript[]`, not in `messages` collection.

**Indexes required:**
```
{ brandId: 1, lastActivityAt: -1 }                         -- customer list sort
{ brandId: 1, status: 1, lastActivityAt: -1 }              -- status filter
{ brandId: 1, channel: 1, status: 1, lastActivityAt: -1 }  -- per-channel filter
{ brandId: 1, type: 1, lastActivityAt: -1 }                -- type filter
```

**Identity resolution (MVP):** enrichment-only — if an incoming interaction adds a new identifier to an existing customer (e.g. order adds email to phone-only record), write it automatically. No merge UI for MVP.

## Decision log

| Decision | Rationale |
|---|---|
| Variant A chosen | Matches CONTEXT.md spec, consistent with existing per-channel inbox UX, gives full context without navigation |
| `customers` as left-panel unit (not conversations) | Operators triage by person, not by individual message thread |
| Urgency badge = most urgent status across all customer conversations | Single clear signal per row; urgency order: `to_manage > human_controlled > ai_controlled > managed > blocked` |
| AI toggle in reply bar (not customer sidebar) | Per README: "Human user can only reply to whatsapp messages when AI is not active" — the toggle is an action in the context of replying |
| Voice and on-site: no reply box | Business rules in README |
| Single `Brand` hardcoded (no auth) | Demo scope; CONTEXT.md says "single hardcoded Brand ID is seeded" |
